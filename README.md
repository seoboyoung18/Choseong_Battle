# 초성배틀 (Choseong Battle)

> 먼저 외치면 이기는 한글 초성 퀴즈

한글 자모 힌트를 보고 사전에 있는 단어를 **가장 먼저** 입력하는 사람이 이기는 2~4인 실시간 멀티플레이 퀴즈 게임입니다.

```
   ㄱ  ㅈ   →  감자 · 기적 · 간장 · 과자 …
   ㅏ  ㅓ   →  사전 · 감정 · 발전 …
  ⬜ 장 ⬜  →  화장품 · 소장품 …
```

친구들끼리 입으로 하던 초성 게임("ㄱㅈ! 되는 말 아무거나 먼저 외쳐!")을 그대로 옮긴 룰이라 설명이 거의 필요 없습니다.

> **지금은 로컬에서 게임을 다듬는 단계입니다.** 토스 미니앱(앱인토스) 출시는 나중에 합니다. 다만 배포 때 반드시 걸릴 것들 — 특히 **소켓 인증이 위조 가능하다는 점** — 은 미리 찾아 [docs/deployment.md](docs/deployment.md)에 적어 뒀습니다. 지금 고칠 필요는 없지만 모르고 있으면 안 되는 것들입니다.

## 빠르게 실행하기

필요한 것: **Node.js 20+**, **Docker**(PostgreSQL·Redis용).

```bash
# 1. 인프라 — PostgreSQL 18 + Redis 7
docker compose up -d
docker compose ps            # 둘 다 healthy 가 될 때까지 기다린다 (첫 실행은 이미지를 받느라 조금 걸린다)

# 2. 서버 설정 · 스키마 · 시드 단어
cd server
cp .env.example .env
npm install
npm run db:migrate           # 스키마 생성 (이미 있으면 실패한다 — 안전장치)
npm run db:seed              # 시드 단어를 넣는다

# 3. 서버
npm start                    # http://localhost:3000

# 4. 클라이언트 (새 터미널)
cd client
npm install
npm run dev                  # http://localhost:5173
```

브라우저에서 열고 닉네임을 넣으면 바로 시작합니다. 로그인은 아직 개발용 임시 계정이라 아무 닉네임이나 됩니다.

> **5173이 이미 쓰이고 있으면** Vite가 5174로 밀립니다. 서버 CORS 허용 목록에 5173·5174를 둘 다 넣어 뒀으니 그대로 동작합니다. 그보다 더 밀렸다면(5175…) `server/.env`의 `CORS_ORIGINS`에 그 포트를 추가하세요 — 안 그러면 소켓 연결이 CORS에서 막힙니다.

### 포트

호스트 포트는 **PostgreSQL 5433 · Redis 6380**입니다. 표준 포트(5432·6379)를 쓰지 않는 이유는 개발 PC에서 다른 프로젝트가 이미 그 포트를 쓰고 있기 때문입니다. 컨테이너 안은 표준 포트 그대로고, `.env.example`이 5433·6380을 가리키므로 그냥 복사하면 맞습니다.

표준 포트로 돌리고 싶으면 `docker-compose.yml`의 `ports`와 `server/.env`를 같이 바꾸세요.

**혼자서 2~4인 대전을 테스트하려면** 탭을 여러 개 엽니다. 계정 id를 `sessionStorage`에 두기 때문에 탭마다 다른 사람이 되고, 새로고침해도 같은 사람으로 돌아옵니다.

### 확인

```bash
# 서버가 붙었는지
curl http://localhost:3000/health

# 단위 테스트 (Redis·PostgreSQL이 떠 있어야 전부 돈다)
cd server && npm test
cd client && npm test

# 종단 스모크 — 소켓 두 개를 붙여 한 판을 끝까지 굴린다 (서버가 떠 있어야 한다)
cd server && node scripts/smoke.js
```

> 인프라를 띄우지 않으면 서버 테스트 52건이 빠집니다. 그 상태를 `test/infra-available.test.js`가 **실패로 잡아** 주므로 통과처럼 보이지 않습니다. 인프라 없이 단위 테스트만 돌리려면 `SKIP_INFRA_TESTS=1 npm test`.

### 사전 — 제대로 놀려면 이걸 해야 합니다

`npm run db:seed`가 넣는 건 **372단어짜리 맛보기**입니다. 이걸로도 게임은 돌아가지만 힌트가 금방 반복되고 못 맞히는 문제가 자주 나옵니다. 원본 XML이 `server/db/krdict/`·`server/db/opendict/`에 있으면 바로 채울 수 있습니다.

```bash
cd server
npm run db:import -- --dry      # 무엇이 들어갈지 먼저 본다
npm run db:import               # 한국어기초사전 → 판정 27,400 · 출제 5,408
npm run db:block                # 차단 목록 적용

npm run db:import:open -- --dry # 우리말샘 (1.8GB라 몇 분 걸린다)
npm run db:import:open          # → 판정 105,096개
```

**임포트 뒤에는 서버를 다시 띄워야 합니다** — 사전은 기동할 때 메모리에 통째로 올립니다. `curl http://localhost:3000/health`의 `dictionary` 값으로 확인하세요.

원본이 없으면 내려받아야 합니다. 기초사전은 로그인이 필요 없고, 우리말샘은 회원 가입이 필요합니다. 출처·라이선스·필터 기준은 [server/db/DICTIONARY.md](server/db/DICTIONARY.md)에 있습니다.

### 게임 화면 배경 (선택)

`client/public/play-bg.jpg`를 두면 플레이 화면 배경으로 자동 적용됩니다. 없으면 기본 그라데이션이 나옵니다. [client/public/README-bg.md](client/public/README-bg.md) 참고.

### 정리

```bash
docker compose down          # 내리기 (DB 데이터는 남는다)
docker compose down -v       # 데이터까지 지우기
```

## 핵심 규칙

### 문제 카테고리 5종

| 카테고리 | 힌트 | 정답 예시 | 글자 수 |
|---|---|---|---|
| 자음 | `ㄱ ㅈ` | 감자, 기적, 간장 | 2~3 |
| 모음 | `ㅏ ㅓ` | 사전, 감정, 발전 | 2~3 |
| 자음+모음 | `ㄹ ㅔ` | 라테, 로켓 | 2~3 |
| 한 글자 공개 | `⬜ 장 ⬜` | 화장품 | 3~4 |
| 종합 | 위 네 가지 혼합 | | 2~4 |

- **자음+모음**은 글자마다 초성 또는 중성 중 하나를 무작위로 제시합니다. (라테 → 1글자째 초성 `ㄹ`, 2글자째 중성 `ㅔ`)
- 같은 카테고리를 선택한 유저끼리 매칭됩니다.

### 라운드 진행 — 선착순

1. 문제 공개와 함께 제한시간 20초 카운트다운
2. 전원 동시 입력 경쟁 → **가장 먼저 유효한 정답을 낸 사람이 라운드 승리**
3. 아무도 못 맞히면 **라운드 번호는 유지하고 문제만 교체** — 모든 라운드는 승자가 나와야 넘어갑니다
4. 설정한 라운드 수를 마치면 종료 (기본 10, 최대 20)

### 점수 — 라운드 승수제

라운드를 먼저 맞히면 1점. 보너스·콤보·감점은 없습니다. 최종 결과는 `6 : 4` 형태의 승수 스코어로 표시됩니다.

동점일 때는 1위 동점만 서든데스 1라운드로 가리고, 그 외 순위는 평균 정답 속도가 빠른 쪽이 상위입니다.

### 정답 판정 — 사전 판정

**힌트 패턴과 일치하고 판정용 사전에 존재하는 단어면 전부 정답입니다.** 주제 제한은 없습니다.

```
힌트 ㄱㅈ  →  감자 ✅  간장 ✅  과자 ✅  기적 ✅  …
```

- 한글 표기만 인정합니다. 알파벳·숫자·특수문자는 입력 단계에서 차단됩니다.
- 사전에 등재된 외래어(라테, 버스)는 인정하되 영어 음차 표현(나이스, 굿)은 인정하지 않습니다.
- 미인정 단어는 **제출 자체가 성립하지 않습니다.** 흔들림 애니메이션과 "등록되지 않은 단어" 피드백 후 즉시 재입력할 수 있으며, 감점이나 입력 잠금은 없습니다.
- 판정·타이머·선착 순위·점수 계산은 **전부 서버에서** 수행합니다.

## 게임 모드

| | 빠른 대전 | 친구 방 | 혼자 연습 | 랭크전 `v1.1` |
|---|---|---|---|---|
| 인원 | 2~4인 | 2~4인 | 1인 | 1대1 고정 |
| 카테고리 | 5종 선택 | 방장 설정 | 5종 선택 | 종합 고정 |
| 라운드 | 10 | 5~20 | 무제한 | 10 고정 |
| 랭킹 반영 | 주간 랭킹 | ❌ | ❌ | 시즌 티어 |

### 친구 방

문제 수(5~20), 카테고리, 비밀번호(선택, 숫자 4자리)를 정해 방을 만듭니다. 들어가는 길은 둘입니다.

- **공개 방 목록** — 홈의 「친구와 하기」에 대기 중이고 자리가 남은 방이 뜹니다. 눌러서 바로 입장하고, 잠긴 방(🔒)은 그 자리에서 비밀번호 칸이 열립니다. 목록은 화면에 들어올 때 한 번 받고 그 뒤로는 새로고침 버튼으로 갱신합니다.
- **6자리 초대 코드** — 코드를 직접 받아 들어갑니다.

방 이름은 `<닉네임>의 방`으로 자동 지정됩니다 — 직접 짓는 입력란은 아직 없습니다.

### 혼자 연습 — 5단계

| 단계 | 제한시간 | 방식 |
|---|---|---|
| 자유 | 무제한 | 패스 가능, 종료 없음 |
| 초보 | 12초 | 연속 도전 |
| 중수 | 8초 | 연속 도전 |
| 고수 | 5초 | 연속 도전 |
| 초고수 | 3초 | 연속 도전 |

시간제 단계는 오답 또는 시간 초과 시 종료되며, 단계·카테고리별 최고 연속 기록이 저장됩니다.

### 랭크전 `v1.1`

1대1 고정, 종합 카테고리 고정, 10라운드. 네 유형을 균등 배분한 뒤 순서만 섞어 출제해 유형 운을 제거합니다.

- 표준 Elo — 시작 1000점, K=32 (초반 10판은 K=64)
- 5판 배치 후 티어 부여: 브론즈 / 실버 / 골드 / 플래티넘 / 다이아 (+ 상위 100인 랭커)
- 시즌 6~8주, 종료 시 소프트 리셋

> **레이팅·시즌 필드는 현재 스키마에 없습니다.** 애초 계획은 MVP 스키마에 미리 넣어 마이그레이션 부담을 줄이는 것이었지만 실제로는 반영되지 않았고, v1.1에서 `users` 테이블 마이그레이션이 필요합니다.

## 랭킹

주간 랭킹의 지표는 **주간 라운드 승수 합산**이며 단위는 "승"입니다.

| 항목 | 규칙 |
|---|---|
| 집계 대상 | 빠른 대전만 (친구 방 제외) |
| 상한 | 주간 상위 20판까지만 집계 |
| 등재 조건 | 주간 3판 이상 플레이 |
| 동점 | 평균 정답 속도가 빠른 쪽이 상위 |
| 리셋 | 매주 월요일 00:00 KST |

<details>
<summary>왜 친구 방을 제외하고 20판 상한을 두는가</summary>

- **담합 차단** — 친구 둘이 2인 비밀번호 방을 파고 한 명이 계속 져주면 승수를 무제한으로 확보할 수 있습니다. 외부에서 보이지 않아 탐지도 어렵습니다.
- **갈아넣기 완화** — 단순 합산은 실력이 아니라 플레이 시간을 측정합니다. 20판 상한은 초반 동기를 남기면서 무제한 누적을 막습니다.
- **인원수 보정은 보류** — 2인 판의 라운드 승리 기대 확률은 50%, 4인 판은 25%입니다. 보정이 계산상 타당하지만 소수점 점수는 납득이 어려워, 매칭이 3~4인으로 채워지는지 확인 후 재검토합니다.

</details>

## 아바타

한복(저고리)을 입은 동물 캐릭터입니다. **완성된 이미지를 쓰지 않고 SVG로 조합해 그립니다** — 파츠 id만 DB(`users.appearance`)에 저장하므로, 나중에 진짜 일러스트로 갈아끼워도 저장된 캐릭터는 그대로 삽니다.

파츠 카탈로그는 [shared/avatar.js](shared/avatar.js) 한 곳에 있고 서버와 클라이언트가 같은 파일을 봅니다. 서버가 이 파일을 갖는 이유는 잠긴 파츠를 입고 오는 요청을 막기 위해서이고, 클라이언트가 갖는 이유는 남의 캐릭터도 id만 받아 그려야 하기 때문입니다.

| 슬롯 | 개수 | 내용 |
|---|---|---|
| 동물 | 8 | 토끼 · 곰 · 고양이 · 다람쥐 · 너구리 · 여우🔒 · 호랑이🔒 · 까치🔒 |
| 한복 | 8 | 쪽빛 · 다홍 · 미색 · 연둣빛 · 자주 · 먹빛 · 금빛🔒 · 하늘🔒 |
| 머리 | 6 | 없음 · 댕기 · 꽃 · 방울 · 족두리🔒 · 갓🔒 |
| 표정 | 5 | 방긋 · 윙크 · 뿌듯 · 놀람 · 새침🔒 |
| 배경 | 6 | 모래 · 민트 · 살구 · 하늘 · 라일락 · 밤🔒 |

사람이 아닌 동물을 택한 이유는 세 가지입니다. 작은 크기에서 **귀 실루엣만으로 식별**되고, 피부색 선택지 부담이 없으며, 동물 이름이 실제 문제로 출제되어 콘텐츠와 이어집니다.

### 해금

🔒 표시 파츠는 플레이로 열립니다. 모든 아이템은 **무료**이고 외형 전용이라 승패에 영향을 주지 않습니다.

| 조건 | 기준 |

새로 열리면 게임 중에 해금 배너가 뜹니다(`unlock.new`).

## 기술 스택

| 영역 | 선택 |
|---|---|
| 클라이언트 | React 19 + Vite (CSR) |
| 서버 | Node.js 20+ / **Express 5** |
| 실시간 | Socket.IO 4 |
| 캐시 | Redis — 매칭 큐, 룸 상태, 선착 락, pub/sub |
| DB | PostgreSQL 18 — 유저, 전적, 단어 사전, 랭킹 |
| 모니터링 | 미도입 |

> 서버는 원래 NestJS로 계획했지만 실제로는 Express로 구현했습니다. 소켓 이벤트 중심이라 DI 컨테이너와 데코레이터가 주는 이점이 크지 않았고, 의존성도 가볍게 유지됩니다.

```
  클라이언트 (React + Vite)            로컬: Vite dev  │  배포: .ait 번들을 앱인토스가 호스팅
        │  실시간 게임 (Socket.IO)     로컬: ws://     │  배포: wss:// 필수
        │  헬스체크 · 공개 방 목록      로컬: http://   │  배포: https://
        ▼
  게임 서버 (Express + Socket.IO)      로컬: npm start │  배포: 호스팅 미정 ⚠
        ├ Redis      매칭 큐 · 룸 상태 · 선착 락 · pub/sub
        └ PostgreSQL 유저 · 전적 · 단어 · 랭킹
```

앱인토스는 **클라이언트 번들만** 호스팅합니다. 서버·Redis·PostgreSQL은 우리가 따로 운영해야 하는데 아직 정한 게 없습니다 → [docs/deployment.md](docs/deployment.md)

### 설계 원칙

- **서버 권위** — 타이머·판정·선착 순위(서버 수신 시각)·점수는 전부 서버 기준. 클라이언트는 입력만 전송합니다.
- **판정 엔진 2종 분리** — ① 패턴+사전 판정(현재) ② 지정 정답 판정(향후 상식·국기 퀴즈용). `rounds.judge_kind`(`DICT` / `FIXED`) 필드를 둬 방·매칭·점수 시스템을 재사용합니다.
- **재접속 복구** — 룸 상태를 Redis에 보관, 30초 내 재접속 시 진행 중 게임에 복귀시킵니다.
- **어뷰징 감지** — 문제 공개 후 0.5초 미만 정답 등 비정상 패턴을 로깅합니다.
- **플랫폼 독립** — 외부 SDK 의존부는 어댑터 계층으로 분리할 계획입니다. 현재는 붙은 SDK가 없습니다.

게임 규칙 상수는 [server/src/config.js](server/src/config.js)의 `RULES` 한 곳에만 둡니다 — 라운드 루프·매칭·판정이 같은 숫자를 봐야 하기 때문입니다.

### 선착 판정 시퀀스

```
Client                Server              Redis         Dictionary
  │  round.submit       │                   │                │
  ├────────────────────▶│                   │                │
  │                     │ 한글 검사·자모 분해·패턴 대조        │
  │                     ├──────────────────────────────────▶ │
  │                     │◀────────────────────────── 등재 O(1)│
  │                     │  SETNX round:winner │               │
  │                     ├──────────────────▶│                │
  │  round.won (전체 브로드캐스트)            │                │
  │◀────────────────────┤                   │                │
```

락을 얻지 못하면 `submit.rejected { ROUND_CLOSED }`가 본인에게만 전송됩니다.

## 단어 데이터

2단 구조로 관리합니다.

| 구분 | 현재 | 용도 |
|---|---|---|
| 출제용 큐레이션 | 5,408개 | 실제 문제로 나가는 단어 |
| 판정용 사전 | 105,096개 | 정답 인정 여부 판단 |

출처는 국립국어원 **한국어기초사전**(출제 + 판정)과 **우리말샘**(판정 전용)이며 둘 다 CC BY-SA 2.0 KR입니다. 어휘 등급이 있는 기초사전만 출제 풀에 넣고, 등급이 없는 우리말샘은 판정에만 씁니다.

- 판정용 사전은 서버 기동 시 메모리 해시셋으로 올려 제출당 **O(1)** 조회합니다. 임포트 후에는 서버를 다시 띄워야 반영됩니다.
- `words` 테이블에 초성열·중성열을 미리 계산해 저장하고, 패턴 역인덱스로 활용합니다.
- 게임 중 **단어 신고** 버튼으로 추가·삭제 요청을 접수합니다(`word_reports`).
- 부적절어는 **출제 금지**(판정은 인정)와 **완전 차단**(출제·판정 모두 제외) 두 단계로 나눕니다. 사전에 있는 말을 판정에서 빼면 "없는 단어"라고 거짓말하는 셈이라, 완전 차단은 아주 좁게 씁니다.
- **런타임 LLM 호출은 금지합니다.** 속도·공정성·비용 문제로, 검수는 오프라인 배치에서만 합니다.

내려받기 절차, 필터 기준, 라이선스 의무, 차단 목록 설계는 [server/db/DICTIONARY.md](server/db/DICTIONARY.md)에 있습니다.

- 3D 입체 버튼(`box-shadow: 0 4px 0 <어두운색>`)으로 캐주얼 게임 특유의 촉감을 유지합니다. 누르면 그 두께만큼 내려앉습니다.

- 폰트는 **Pretendard**(본문)와 **Jua**(타이틀·힌트 타일). 둘 다 무료 라이선스이고 지금은 CDN에서 받습니다. Jua는 굵기가 하나뿐이라 `font-weight`를 올리지 않습니다 — 합성 볼드가 되어 획이 뭉갭니다. 받지 못해도 시스템 서체로 떨어져 읽히기만 합니다.

색 값은 전부 [client/src/styles/tokens.css](client/src/styles/tokens.css)의 `:root` 한 곳에 있습니다. 여기만 바꾸면 전 화면이 재도색됩니다.

### 나중 — 배포

출시할 때 반드시 걸립니다. 지금 고칠 필요는 없지만 설계를 바꾸는 것들이라 미리 알고 가야 합니다. 전체 목록과 순서는 [docs/deployment.md](docs/deployment.md)에 있습니다.

- 🔴 **소켓 인증이 위조 가능합니다.** 서버가 클라이언트가 보낸 `userId`를 그대로 믿습니다. 남의 id만 알면 그 계정으로 접속해 전적·랭킹을 조작할 수 있습니다. 코드 주석도 "절대 이 상태로 배포하면 안 된다"고 경고합니다. 토스 로그인을 붙이며 JWT 검증으로 교체해야 합니다.
- 🔴 **서버를 어디서 돌릴지 정한 적이 없습니다.** 앱인토스는 클라이언트 번들만 호스팅합니다. 게임 서버·PostgreSQL·Redis는 따로 운영해야 하고 `wss://`가 필수라 도메인·TLS가 필요합니다. 무료 호스팅은 유휴 시 잠드는 경우가 많은데 소켓 게임에는 치명적이니, 고를 때 이 조건을 먼저 봐야 합니다.
- 🔴 **게임 등급분류 증빙** — 게임 앱은 제출이 의무이고 소요 기간이 깁니다.

그 뒤로 토스 로그인·`.ait` 번들·닉네임 비속어 필터·광고·Sentry·성능 측정이 이어집니다.
