# 배포 준비

> 목표는 앱인토스(토스 미니앱) 출시다. 지금은 로컬에서 게임을 다듬는 단계지만
> **배포를 전제로 작업한다** — 나중에 뜯어고치면 비싼 결정들을 먼저 정리해 둔다.
>
> 이 문서는 조사 결과와 현재 코드를 대조한 것이다. SDK 버전·심사 기준·수수료는
> 바뀔 수 있으므로 착수 전에 앱인토스 공식 문서를 다시 확인한다.

## 1. 배포 구조 — 아직 정해진 게 없다

**가장 큰 공백이다.** 앱인토스는 *클라이언트 번들만* 호스팅한다. 이 게임은 서버 권위
구조라 게임 서버·PostgreSQL·Redis가 **따로 돌아야 하는데, 어디서 돌릴지 정한 적이 없다.**
저장소에도 흔적이 없다 — Dockerfile 없음, CI 설정 없음, 배포 스크립트 없음.

```
[토스 앱]
  └ 미니앱 클라이언트 (.ait 번들)        ← 앱인토스가 호스팅
        │  wss://  게임               ← 여기부터는 우리가 운영해야 한다
        ▼
  게임 서버 (Express + Socket.IO)      ← 호스팅 미정
        ├ Redis                       ← 미정 (관리형? 직접?)
        └ PostgreSQL                  ← 미정
```

정해야 할 것:

| 항목 | 왜 미리 정해야 하나 |
| --- | --- |
| 서버 호스팅 | `wss://`가 필수라 **도메인 + TLS 인증서**가 있어야 한다. 무료 티어는 유휴 시 잠드는 경우가 많은데, 소켓 게임에는 치명적이다 |
| PostgreSQL | 판정 사전 10만 건 + 전적. 관리형이면 비용, 직접이면 백업 책임 |
| Redis | 룸 상태·선착 락. 재시작하면 진행 중인 판이 날아가므로 가용성이 중요 |
| 비용 | 월 운영비 상한을 정해야 호스팅 선택지가 좁혀진다 |
| 배포 방식 | 서버 컨테이너 이미지 + 무중단 배포 여부. 지금은 `npm start`뿐이다 |

> 로컬용 `docker-compose.yml`은 있지만 **운영에 쓸 물건이 아니다** — 비밀번호가 평문이고
> 포트가 열려 있다. 서버 자체를 담는 Dockerfile도 아직 없다.

## 2. 배포를 막는 것

심각도 순이다. 위 세 개는 이게 해결되기 전에는 출시 자체가 불가능하다.

### 🔴 1. 소켓 인증이 위조 가능하다

`server/src/index.js`의 소켓 미들웨어가 클라이언트가 보낸 `handshake.auth.userId`를
**그대로 믿는다.** 코드 주석이 스스로 경고하고 있다:

> `handshake.auth의 값을 그대로 신뢰하므로 절대 이 상태로 배포하면 안 된다.`

남의 `userId`만 알면 그 사람 계정으로 접속해 전적·랭킹·캐릭터를 조작할 수 있다.
토스 로그인을 붙이면서 **JWT 검증으로 교체**해야 한다. 클라이언트에도 자리는 이미
표시돼 있다(`client/src/socket/client.js`의 `TODO: 토스 로그인 붙으면 auth에 JWT를 싣는다`).

### 🔴 2. 서버 호스팅·TLS 미결정

위 1절. `wss://`는 플랫폼 필수 요건이라 우회할 수 없다.

### 🔴 3. 게임 등급분류 증빙

게임 앱은 등급 심의 증빙 제출이 **의무**다. 미이행 시 시정 권고·수사 의뢰·행정처분 대상.
소요 기간이 길어 **가장 먼저 착수해야 한다.** 자세한 내용은 아래 「등급분류」.

### 🟠 4. 토스 로그인 미연동

현재는 `client/src/App.jsx`가 `dev-xxxx` 임시 계정을 `sessionStorage`에 만들어 쓴다.
해당 함수에 `TODO: 토스 로그인으로 교체하면 이 함수는 통째로 사라진다` 주석이 있다.
1번과 같이 처리된다.

### 🟠 5. `.ait` 번들 파이프라인이 없다

앱인토스 SDK가 **설치돼 있지 않다**(`client/package.json`에 의존성 없음).
현재 `npm run build`는 평범한 Vite 빌드라 `dist/`만 나온다.

```bash
npm run build          # <서비스명>.ait 번들 생성
npx ait deploy         # CI/CD 업로드 (SDK v1.4.0+, API 키 필요)
```

### 🟠 6. 닉네임 비속어 필터

닉네임이 랭킹에 공개 노출되므로 등급분류의 「언어의 부적절성」 대응에 필요하다.
사전 낱말 차단(`server/src/words/blocklist.js`)은 구현돼 있지만 **닉네임에는 적용되지 않는다** —
`server/src/db/store.js`의 `upsertUser`·`updateProfile` 경로에 검사가 없다.

### 🟡 7. 비밀값 관리

`server/src/config.js`의 PostgreSQL 비밀번호 기본값이 `ssafy`이고 `.env.example`에도
평문으로 들어 있다. 로컬 기본값이라 지금은 문제없지만, 운영 환경변수를 붙이기 전에
기본값을 지우고 **없으면 기동 실패**하도록 바꾸는 편이 안전하다.

### 🟡 8. 광고

결과 화면 진입 시 1회 노출. `client/src/screens/Result.jsx`에 위치만 주석으로 표시돼 있다.
아래 「광고 규칙」 참고.

### 🟡 9. Sentry · 성능 측정

모니터링이 없다. 성능 요건(최초 화면 10초, 인터랙션 2초)도 측정한 적이 없다.

### 🟡 10. 서체를 번들에 넣기

Pretendard와 Jua를 지금은 CDN(`cdn.jsdelivr.net`·`fonts.googleapis.com`)에서 받는다
(`client/index.html`). 로컬에서는 편하지만 출시용으로는 두 가지가 걸린다.

- **런타임 외부 의존** — CDN이 느리거나 막히면 첫 화면이 늦어진다. 최초 화면 10초
  제한이 있고, 파비콘을 인라인으로 둔 것도 번들을 자체 완결적으로 두려던 것이다.
- **서체가 디자인의 일부다** — 떨어지면 시스템 서체로 바뀌어 화면 인상이 달라진다.

`client/public/`에 woff2를 넣고 `@font-face`로 바꾸면 된다. 한글 서브셋만 담으면
용량도 작다 (번들 제한은 100MB).

## 3. 이미 충족한 것

배포를 염두에 두고 만들어 둔 부분이다. 다시 할 필요 없다.

| 항목 | 근거 |
| --- | --- |
| CSR 전용 (SSR 금지) | Vite SPA 빌드 |
| `eval`·`new Function`·history 조작 없음 | 전수 검색 0건 |
| Safe Area 미침범 | `env(safe-area-inset-*)` 적용 |
| 종료 확인 모달 | `components/ConfirmDialog.jsx` |
| 사운드 On/Off + 백그라운드 즉시 정지 | `client/src/sound.js`, 마이페이지 토글 |
| CORS 허용 목록 환경변수화 | `server/.env`의 `CORS_ORIGINS` |
| 헬스체크 | `GET /health` — Redis·PostgreSQL 점검 후 degraded면 503 |
| 우아한 종료 | `SIGINT`·`SIGTERM` 처리 |
| 번들 크기 | 약 290KB JS + 24KB CSS (제한 100MB) |
| 서버 권위 구조 | 타이머·판정·선착 순위·점수 전부 서버 |

## 4. 앱인토스 파이프라인

`.ait` 업로드 → QR 테스트(최소 1회 필수) → 검토 요청 → 승인 → 출시

- 앱 정보 검토 1~2영업일, 번들 검토 최대 3영업일, **게임 카테고리는 7영업일 이상 소요 가능**
- 출시·롤백 모두 전체 사용자에게 즉시 반영된다
- 테스트 스킴은 `intoss-private://` + `_deploymentId`. `intoss://`는 출시 후에만 동작하므로 **초대 링크 딥링크는 출시 전 실스킴 검증이 불가능**하다

### 서버 CORS 허용 목록 (SDK 3.x)

```
https://<appName>.web.tossmini.com          실서비스
https://<appName>.private-web.tossmini.com  QR 테스트
```

`server/.env`의 `CORS_ORIGINS`에 쉼표로 넣으면 된다.

## 5. 플랫폼 제약 대조

| 항목 | 요건 | 현재 |
| --- | --- | --- |
| 사용 연령 | 만 19세 이상만 이용 가능 | — |
| 번들 | 압축 해제 100MB 이하 | ✅ 여유 |
| 렌더링 | CSR / SSG만 (SSR 금지) | ✅ |
| WebSocket | `wss://`만 허용 | ❌ 로컬 `ws://`. 호스팅 결정 필요 |
| 보안 | `eval` 등 외부 코드 실행 금지, history 조작 금지 | ✅ |
| 성능 | 최초 화면 10초 이내, 인터랙션 2초 미만 | ⚠️ 미측정 |
| 사운드 | On/Off 필수, 백그라운드 즉시 종료·복귀 시 재생 | ✅ |
| 화면 | 인게임 풀스크린, Safe Area 미침범, 종료 확인 모달 | ✅ |
| 광고 | 일시적 화면 노출 금지, 사전 프리로드 필수 | ❌ 미착수 |

### 광고 규칙

**결과 화면 진입 시점 1회**만 노출한다. 매칭 대기·라운드 전환·승리 연출은 모두
"일시적 화면"에 해당해 광고를 넣을 수 없다. 로드 실패 시에는 광고를 건너뛰고 결과
화면으로 진행해 게임 흐름을 막지 않는다.

## 6. 게임 등급분류

| 경로 | 내용 |
| --- | --- |
| 오픈마켓 선출시 | 구글 플레이·앱스토어·원스토어 등에 먼저 출시해 자체등급분류 획득 |
| 게임물관리위원회 직접 심의 | 등급분류증명서를 PDF로 제출 |

본 프로젝트는 **직접 심의**를 택한다. 오픈마켓 경로는 등급분류를 받기 위해 앱을 하나 더
만들어야 하고, 두 버전이 동일 게임임을 플레이 화면 각 2장으로 증명해야 하는 부담이 있다.

예상 등급은 **전체이용가**다. 내용정보 7개 항목 중 선정성·폭력성·공포·약물·범죄·사행성은
해당 없으며, 현금성 보상·확률형 아이템도 없다. 다만 닉네임이 랭킹에 공개 노출되므로
비속어 필터가 필요하다(2절 6번).

> 게임 이용등급과 플랫폼 연령 제한은 별개다. 게임이 전체이용가여도 앱인토스는
> 만 19세 이상에게만 제공된다.

## 7. 수익화

| | 내용 |
| --- | --- |
| 광고 | 결과 화면 진입 시 1회 |
| 도입 계획 없음 | 인앱 결제, 코스메틱 판매, 확률형 아이템 |

아바타 아이템은 전부 무료이며 승수·연속 정답·친구 초대로 해금한다. 외형 전용이라
승패에 영향을 주지 않는다. 사업자 등록이 선행 과제다.

## 8. 순서

앞 단계가 뒤 단계를 막는 순서로 적었다.

| 단계 | 할 일 |
| --- | --- |
| 0 | **게임 등급분류 증빙 착수** · 사업자 등록 — 기간이 길어 다른 작업과 병행한다 |
| 1 | **배포 구조 결정** — 서버 호스팅·DB·Redis·도메인·비용 상한 (1절) |
| 2 | 서버 Dockerfile + 배포 스크립트, 운영 환경변수·비밀값 분리 |
| 3 | **토스 로그인 + JWT 검증** — 소켓 인증 위조를 여기서 막는다 (2절 1·4번) |
| 4 | SDK 어댑터 계층(로그인·공유·광고) · `.ait` 번들 파이프라인 |
| 5 | `wss://` 전환, CORS를 tossmini 도메인으로, 닉네임 비속어 필터 |
| 6 | 광고 연동, Sentry, 성능 측정 |
| 7 | QR 테스트 → 클로즈드 테스트(만 19세 이상 20인) → 검토 요청 |

**플랫폼 독립** — 토스 SDK 의존부(로그인·공유·광고)는 어댑터 계층으로 분리해 추후 이식을
쉽게 한다. 지금은 어댑터가 없고 `App.jsx`가 임시 계정을 직접 만들고 있으므로, 붙일 때
어댑터부터 만들고 `App.jsx`를 그 뒤로 옮긴다.
