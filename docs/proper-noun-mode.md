# 고유명사 모드 — 출처 조사

> **인명·운동선수·캐릭터·포켓몬 22,126개를 넣었다. 영화·만화·애니는 아직이다.** 아래는 그 판단 근거이고,
> 막힐 줄 알았던 데이터 출처 문제가 해소됐다는 것이 요지였다.
>
> 조사일 2026-10-01. 라이선스와 데이터 수량은 바뀔 수 있으니 착수 전에 다시 확인한다.

## 어떤 모드인가

영화 제목·애니메이션·만화·캐릭터·배우·가수 이름 같은 **고유명사도 정답으로 인정하는**
모드다. 별도 퀴즈가 아니라 **기존 모드에 더하는** 것이다 — 힌트는 지금처럼 일반
사전에서 나오고, 답으로 칠 수 있는 낱말만 늘어난다.

그래서 라운드는 쉬워지는 방향이다. 답이 줄어드는 게 아니라 늘어난다.

### 범위를 좁히는 규칙

데이터를 넣을 때 지키는 규칙이다. 이게 있어서 표기 흔들림 문제가 작아진다.

- **2~4글자 순한글만.** 기존 제약(FR-G1)과 같다. `어벤져스엔드게임`은 애초에 안 들어온다.
- **한국어 정식 표기 하나만.** `귀멸의칼날`은 넣고 `키메츠노 야이바`는 넣지 않는다.
- **줄임말은 넣지 않는다.** `귀칼` 같은 것.
- **제목·이름 텍스트만.** 이미지·포스터·초상을 쓰지 않으므로 그쪽 권리 문제가 없다.

## 출처 비교

| 출처 | 라이선스 | 상업 이용 | 판정 |
| --- | --- | --- | --- |
| **위키데이터** | **CC0** (퍼블릭 도메인) | 가능. **출처 표시 의무도 없음** | ✅ 최적 |
| 한국어 위키백과 | CC BY-SA 4.0 | 가능 (출처 표시 + 동일조건) | ✅ 가능 |
| **나무위키** | CC BY-NC-SA 2.0 KR | **불가 — NC(비영리) 조건** | ❌ 탈락 |
| KOBIS 오픈API (영화진흥위원회) | 공공데이터. 무료 키, 심사 없음 | 데이터셋별 이용허락범위 확인 필요 | ⚠️ |
| TMDB 등 상용 영화 DB | API 이용약관 | 재배포·캐싱 제한이 통상 있음 | ⚠️ |

**나무위키는 쓸 수 없다.** 결과 화면에 광고를 넣기로 한 이상 상업적 이용이고,
NC 조건이 그것을 막는다.

**위키데이터가 압도적으로 유리하다.** CC0는 저작권을 포기한 것이라 출처 표시
의무조차 없다. 기초사전·우리말샘 때문에 이미 지고 있는 CC BY-SA의 저작자 표시·
동일조건 의무가 **더 늘지 않는다**는 뜻이다 (DICTIONARY.md 「라이선스」 참고).

## 실제로 얼마나 있나 — 실측

위키데이터 SPARQL 엔드포인트에 직접 던져 **2~4글자 순한글**만 셌다.

| 분류 | 2~4글자 순한글 | 한국어 레이블 전체 |
| --- | --- | --- |
| 한국 배우·가수 이름 | **9,538** | — |
| 영화 제목 | **7,035** | 31,148 |
| 캐릭터 | **3,199** | — |
| 만화 시리즈 | **288** | 2,125 |
| 애니메이션 | **130** | 1,390 |

현재 출제 풀이 5,402개다. **인물과 영화만으로 그보다 많다.** 한국인 이름은 대부분
3글자라 글자 수 제약과 잘 맞는다.

### 애니·만화는 구조적으로 안 맞는다

수가 적은 이유가 길이 제약 때문이 아니다. 만화는 한국어 레이블 2,125개 중
**공백·비한글을 빼면 366개**만 남고, 거기서 2~4글자로 줄여도 288개다. 즉 **83%가
공백·비한글 단계에서 날아간다.**

한국어 작품 제목이 대개 구(句)여서다 — `귀멸의 칼날`·`진격의 거인`·`강철의 연금술사`.
공백을 지워 붙여 써도 `귀멸의칼날`은 6글자라 2~4 제약에 안 들어온다. 공백을 지우는
처리를 넣으면 만화 288→390, 애니 130→179로 늘지만 그래도 몇백 개다.

`원피스`·`데스노트`·`블리치`처럼 **짧은 제목만 들어온다.**

### 품질 — 숫자를 그대로 믿으면 안 된다

표본을 뽑아 보면 아는 이름이 많지 않다.

```
만화   연짱아빠 · 데빌맨 · 시벨 · 플루토 · 토리코 · 데스노트 · 연공 · 바키 ·
       매일엄마 · 피안도 · 카나메모 · 소녀춘 · 리미트 · 사쿠란 · 아네도킷
애니   길가메시 · 이즈모 · 짱켄맨 · 가키데카 · 카이트 · 문토 · 연희 · 대악사 ·
       마룡전기 · 껍질소녀 · 센류소녀 · 마기 · 포코냥 · 치미모 · 스타잔
캐릭터 백두산 · 팔라딘 · 라타푸아 · 시레누 · 엘레나 · 간피 · 플로라 · 하이바오 ·
       인페르노 · 홍수려 · 아이시클 · 타투드맨 · 디스맨 · 우스타낙 · 구데타마
```

위키데이터는 전수 데이터베이스라 우리말샘과 같은 성격이다 — 다 싣지만 대부분
아무도 모른다. **판정에만 쓰면 무해하다.** 아무도 `아네도킷`을 치지 않으므로 손해가
없고, `데스노트`·`구데타마`를 칠 수 있게 되는 이득만 남는다.

반대로 **출제에 쓰려면 이 상태로는 안 된다.** 기초사전(등급 있음)만 출제에 쓰고
우리말샘은 판정에만 쓰는 지금 구조와 똑같은 문제이고, 똑같이 큐레이션이 필요하다.

```sparql
# 영화 — https://query.wikidata.org/sparql?format=json&query=...
SELECT (COUNT(DISTINCT ?x) AS ?n) WHERE {
  ?x wdt:P31 wd:Q11424 ; rdfs:label ?l .
  FILTER(lang(?l) = 'ko')
  FILTER(STRLEN(?l) >= 2 && STRLEN(?l) <= 4)
  FILTER(REGEX(?l, '^[가-힣]+$'))
}

# 한국 배우·가수
SELECT (COUNT(DISTINCT ?x) AS ?n) WHERE {
  ?x wdt:P27 wd:Q884 ; wdt:P106 ?job ; rdfs:label ?l .
  VALUES ?job { wd:Q33999 wd:Q177220 }
  FILTER(lang(?l) = 'ko')
  FILTER(STRLEN(?l) >= 2 && STRLEN(?l) <= 4)
  FILTER(REGEX(?l, '^[가-힣]+$'))
}
```

### 타입 ID를 찾는 법

애니·만화·캐릭터는 처음에 19·33·270개밖에 안 잡혔다. `애니메이션(Q1107)` 같은
상위 개념으로 조회했기 때문인데, 실제 항목은 하위 유형에 달려 있다. 상위 타입을
전개하는 `wdt:P31/wdt:P279*` 쿼리는 공개 엔드포인트가 못 견딘다(504·429).

대신 **아는 작품 몇 개의 `P31`을 직접 읽어** 쓰이는 타입을 알아냈다.

```bash
# 도라에몽·짱구·슬램덩크 → 전부 Q21198342
curl -H 'User-Agent: <앱이름>/1.0 (<연락처 URL>)' \
  'https://www.wikidata.org/w/api.php?action=wbgetentities&format=json&props=claims&ids=Q235311'
```

| 분류 | 쓰이는 타입 |
| --- | --- |
| 만화 | `Q21198342` 일본의 만화 시리즈 · `Q8274` 만화 |
| 애니 | `Q63952888` 일본 TV 애니메이션 시리즈 · `Q1107` · `Q220898` OVA |
| 캐릭터 | `Q95074` 가공인물 · `Q15632617` 허구의 사람 · `Q3658341` 문학작품의 등장인물 · `Q15773347` 영화 등장인물 · `Q15773317` TV 시리즈 캐릭터 · `Q15711870` 애니메이션 캐릭터 · `Q1114461` 만화 등장인물 · `Q28020127` 허구의 휴머노이드 |

> 위키미디어 API는 **연락처가 담긴 User-Agent를 요구한다.** 없으면 JSON 대신
> 거부 메시지가 돌아와 파서가 깨진다.

## 남은 실무 문제

### 1. 순증가분 — 실측했다

레이블 목록을 전부 받아 `words` 105,120행과 맞춰 봤다.

| 분류 | 수집 | 이미 있음 | **새로 들어옴** | 새것 비율 |
| --- | --- | --- | --- | --- |
| 배우·가수 | 8,576 | 880 | **7,696** | 90% |
| 영화 | 6,031 | 2,407 | **3,624** | 60% |
| 캐릭터 | 2,963 | 919 | **2,044** | 69% |
| 만화 | 286 | 45 | **241** | 84% |
| 애니 | 127 | 16 | **111** | 87% |
| **합집합(중복 제거)** | **17,386** | **3,934** | **13,452** | 77% |

판정 사전이 105,096 → **약 118,500개**로 늘어난다 (+12.8%).

사람 이름이 가장 많이 새로 들어온다(90%) — 한국 인명이 일반 명사와 겹치는 일이
드물어서다. 영화가 가장 많이 겹친다(40%) — 제목이 평범한 낱말인 경우가 많다.

새로 들어올 낱말 표본:

```
배우·가수  제동화 · 권기하 · 한재범 · 이철희 · 유지하 · 차은채 · 홍주희
영화      고질라 · 혹성탈출 · 인셉션 · 아르고 · 원티드 · 투모로우 · 황후화
캐릭터     손오반 · 나나치 · 유바바 · 마히토 · 그웬 · 가로우 · 용가리
만화      데스노트 · 주술회전 · 보루토 · 유녀전기 · 단다단 · 불새 · 배가본드
애니      모노노케 · 정글북 · 소녀전선 · 공중그네 · 조이드 · 요괴인간
```

아는 이름이 분명히 늘었다. 다만 인명 쪽은 대부분 모르는 사람이다 — 판정에만
쓰면 무해하지만 숫자를 "쓸모 있는 13,452개"로 읽으면 안 된다.

### 2. 성인물이 섞여 들어온다 — 지금 차단 목록으로는 못 막는다

영화 목록을 끝까지 훑다가 발견했다. 새로 들어올 제목에 이런 것들이 있다.

```
엄마애인 · 음란기생 · 옆집여자 · 초대남 · 착한불륜 · 청불학원 · 불륜가족
교회누나 · 어린장모 · 어린이모 · 사촌누나 · 섹남섹녀
```

**기존 `BLOCKED`·`NOT_SERVED`는 이것을 못 잡는다.** 손으로 적은 43개짜리 목록이고,
이런 조어는 거기 없다. 그대로 넣으면 사전에 공들여 만든 필터를 통째로 우회한다.

판정에만 넣어도 안전하지 않다. DICTIONARY.md에 적어 둔 그대로다 — **판정 인정은
곧 노출이다.** 라운드를 이긴 낱말은 `round.won`으로 방 전체 화면에 뜨고, 채팅이
없는 이 게임에서 그것이 남에게 글자를 보낼 수 있는 유일한 통로다.

#### 장르 태그로 1차 필터는 된다

위키데이터가 이 작품들에 장르 `Q599558`(에로 영화)를 달아 두었다. 확인한 결과:

| | 개수 |
| --- | --- |
| 에로 영화 태그가 붙은 2~4글자 순한글 제목 | 269 |
| 그중 이미 사전에 있는 낱말 | 82 |
| 새로 들어올 영화 3,624개 중 태그가 붙은 것 | **187 (5.2%)** |

다만 **태그만으로 끝나지 않는다.**

- 태그는 `박쥐`·`정사`·`열쇠`처럼 **평범한 낱말**도 함께 잡는다. 이미 사전에 있는
  말이라 빼면 안 된다 (82개가 여기 해당).
- `쌍화점`·`어우동`·`미인도`·`주홍글씨`처럼 **멀쩡한 작품**도 이 장르에 들어 있다.
- 태그가 빠진 작품이 없다는 보장이 없다.

결국 사전을 들여올 때와 같은 2단 구조가 필요하다 — **자동 표시로 1차, 사람이 2차.**
지금 `isDerogatory`(사전 표시)와 `NOT_SERVED`(손 목록)가 하는 역할 그대로다.

## 결정할 것 — 판정에만 넣을 것인가

"인정되는 모드"라는 말대로라면 **판정에만 추가**(`is_curated = false`)다. 힌트는
지금처럼 일반 사전에서 나오고 답만 늘어난다. 순수하게 쉬워지는 방향이고 난이도를
다시 잴 필요가 없다.

다만 그러면 `오징어게임` 같은 낱말이 **문제로 출제되지는 않는다.** 고유명사가
힌트로도 나오길 원하면 출제 풀에도 넣어야 하고, 그때는 난이도를 따로 재야 한다
(`npm run words:hints`가 그대로 쓰인다).

## 결론

**데이터는 충분하고 라이선스도 깨끗하다. 남은 건 하나 — 성인물 필터다.**

- 출처: 위키데이터(CC0). 추가 의무 없음
- 순증가: **13,452개**. 판정 사전이 12.8% 늘어난다
- 값어치 순서: 인물(7,696) · 영화(3,624) · 캐릭터(2,044) ≫ 만화(241) · 애니(111)
- **착수 전 반드시 풀 것**: 에로 영화 제목이 섞여 들어온다. 장르 태그로 187개를
  1차로 걸러낼 수 있지만 그것만으로는 부족하고, 사전 들여올 때와 같은
  **자동 1차 + 사람 2차** 구조가 필요하다

애니·만화는 몇백 개뿐이라 **이것만으로 모드를 만들 이유는 못 된다.** 하지만
인물·영화·캐릭터와 함께 넣는 비용은 거의 없다.

## 다음 단계

1. 성인물 필터를 설계한다 — 장르 태그 외에 어떤 신호를 쓸지, 사람 검수를 어디에
   넣을지. `npm run words:review`가 그 자리에 있다
2. 작게 넣어 본다. 인물부터가 가장 안전하다 — 성인물 문제가 없고 순증가가 가장 크다
3. 넣은 뒤 `npm run words:hints`로 난이도를 다시 잰다. 답이 늘어나는 방향이라
   나빠질 일은 없지만, 숫자로 확인하는 게 이 저장소 방식이다

### 재현

```bash
# 레이블 수집 — JSON은 제어문자로 깨질 수 있어 XML로 받는다
curl -H 'User-Agent: <앱>/1.0 (<연락처>)' \
     -H 'Accept: application/sparql-results+xml' \
     --get --data-urlencode 'query=SELECT ?l WHERE { ... }' \
     https://query.wikidata.org/sparql
```

`SELECT DISTINCT` + `REPLACE()`를 쓰면 공개 엔드포인트가 못 견딘다(25분 넘게 응답
없음). 필터만 서버에 맡기고 **중복 제거는 받아서 하는 쪽**이 빠르다.
